# Summarize SDSC

The scripts sit next to this file (`tools/cost_model/summarize-sdsc/` in torch-spyre), so paths below are relative to this skill's directory.
Simplest path: the `sdsc` launcher in this directory.

- `sdsc capture [-d DIR] -- <compile command>` runs the command with `TORCHINDUCTOR_CACHE_DIR=DIR`, `SPYRE_DUMP_COST=1`, `SPYRE_DUMP_COST_FILE=DIR/cost_dump.log` and `SPYRE_DUMP_COST_EXPR_FILE=DIR/cost_expr.jsonl`, so artifacts and both dumps land together (default DIR `~/sdsc_runs/<timestamp>`).
- `sdsc report [DIR]` prints the box table to stdout; `--format github` makes it collapsible Markdown and `--out FILE` saves it instead; `sdsc tui [DIR]` opens the browser; `sdsc shot [DIR] [FILE.svg]` renders a headless screenshot. DIR defaults to the newest `~/sdsc_runs/*` or `/tmp/torchinductor_*`.
- `sdsc diff DIR_A DIR_B` compares two captured runs: the whole-run totals side by side, then only the ops whose plan differs. This is the right tool for "what did my planner change" -- an op planned identically is silence.
- Both scripts pick up `cost_dump*.log`, `cost_expr*.jsonl` and `probe*.json` found in DIR or its parent automatically (`--no-auto` disables), so `--cost`/`--cost-expr`/`--probe` are only needed for dumps kept elsewhere.

Without the launcher, run `batch_summarize_sdsc.py` from this directory using the Bash tool with `python3`.

- If the user provided a directory path as an argument, pass it as the first positional argument to the script.
- If no argument was given, find the most recent `/tmp/torchinductor_*/` directory (use `ls -dt /tmp/torchinductor_*/`) and pass that as the argument.
- If the user provides (or asks to include buffer names from) a `SPYRE_INDUCTOR_LOG=1 SPYRE_INDUCTOR_LOG_LEVEL=DEBUG` log, pass it via `--log FILE`. This annotates each op's OUTPUT row with its buffer name (`bufN`), parsed from the log's `spyre_kernel` `kernel_store` lines and mapped through the `.py` LoopSpec/OpSpec tree. Without `--log`, no buffer names are shown.

Output options:

- `--format github` renders Markdown (`##` headings, a bullet list, a pipe table) for a GitHub PR or issue comment, a gist, or an `.md` file; `--format html` renders an HTML table; the default `text` draws the box table with a rule between ops. Multi-line cells become `<br>` in Markdown.
- `--collapsible` (with `--format github`) groups ops under a heading per kernel and wraps each op in a `<details>` block that GitHub renders collapsed: the summary line is the op, cores, what it is, its json file, LX occupancy and predicted time; the body is the op's full tensor table.
- `--out FILE` writes the report to FILE and prints only the path. Use `--format github --collapsible --out summary.md` for GitHub and `--out summary.txt` for a Slack file upload (Slack has no table markup).
- `--basic` is the compact column set (the original columns plus What); `--no-what` drops the leading `What (-> consumer)` column.
- `--cost FILE` joins a cost dump. Capture it during the compile with `SPYRE_DUMP_COST=1 SPYRE_DUMP_COST_FILE=/path/cost.log` (the file is appended to, so use a fresh path; without `SPYRE_DUMP_COST_FILE` the dump goes to stderr) from the same run that produced the artifacts. Each kernel is priced once as a bundle; the report shows each op's HBM-share attribution of that time (`12.3 us of 1311.4 us`), its read/write/LX bytes, and `as <name>` when the dump's op name differs (a shuffle materialized from a clone). Ops are matched by Inductor node name and shared input buffers, or by byte count for single-op copy kernels; the header reports how many matched.
- `--cost-expr FILE` joins the solver's own objective, dumped by the co-optimizing allocator when `SPYRE_DUMP_COST_EXPR_FILE=/path/expr.jsonl` is set during the compile (one JSON line per solved graph; appended, use a fresh path; needs torch-spyre with the dump hook, PR #4595 or later). The report gains an `Objective term` column: the op's bundle term evaluated under the plan the solver chose, and `if HBM: +40.0 us` / `if LX: -80.0 us`, the same term with this op's residency flipped, which is what its placement is worth to the objective. The TUI detail pane also lists the op's own terms of the bundle expression (the additive terms that mention its `is_lx`, `division` or `split` symbols, with their value and the same terms under the flip), its symbols with their solved values, the kernel objective, and relayout charges whose source is this op. The flip is evaluated with every other decision held fixed; a plan that actually moves the buffer may need other divisions to change (pricing that means re-solving with the buffer pinned, which this tool does not do). Graphs the co-optimizer prices as one bundle show the whole-kernel value with an `(N-op bundle)` note; the per-op information is the flip delta.
  A dump from PR #4656 or later also carries the core divisions, and the detail pane gains a `core division` line -- the division the output buffer got and the candidates it was chosen from -- followed by one `gate` line per producer edge giving the `(parent, consumer)` division pairs the residency gate admitted and whether the plan took one of them.
  A pair the gate admits that the plan did not take is an LX residency the chosen division gave up; an edge with no pair at all is one the gate forbids however either side divides (issue #4655 was of that second kind).
- The dump also carries the plan's PROVENANCE, and the report uses it to explain rather than just display. `Cores` reads `6 of 8` against the cap that compile actually had -- `sencores` is per compile, and spyre-inference caps the head-major attention graph to 8 while the rest of the model stays at 32, so a bare `6` reads as 26 cores wasted when it is not. The header warns when a plan is `FEASIBLE` rather than `OPTIMAL`, when the solve hit its time limit, or when the objective could not be lowered and the plan came from the fallback -- all of which look identical in the table. Occupancy is measured against the planner's own LX budget instead of the CLI default, and residency reasons come from the record, so `--probe` is only needed for dumps written before that.
- Residency REASONS are the allocator's own words for why a buffer is not in LX (`op not allowed`, `spilled by solver (no residency benefit / no room)`, `partial/offset read`). Nothing in the SDSC output records them: by then the decision is a fact, not a reason. The cost-expression dump records them (PR #4738 or later); `--probe FILE` reads the same reasons from an older residency probe JSON, for runs captured before that. The reason appears under the address on the op's OUTPUT row, in full in the TUI detail pane, and as a histogram in the header.
  Read the header line for the shape of a run: one dominated by `spilled by solver` was a cost decision, so look at the objective; one dominated by a gate reason never reached the solver at all, which is a different thing to go and fix.
- `--diff DIR` prints the comparison `sdsc diff` wraps. Kernels are paired by their op-name sequence (the kernel directory is a content hash and changes with the code), ops within a kernel by position or by a longest-common-subsequence, so an inserted shuffle shifts nothing after it. Only the facts BOTH runs recorded are compared -- diffing a run whose dump records residency reasons against an older one without them would otherwise report every op as changed -- and the dropped kinds are named under the table.
- `--width COLS` fits the diff's text tables to COLS columns by wrapping the widest cells (`0`: never wrap). The default is `$COLUMNS`, else the terminal's width; a pipe or `--out` is left unwrapped, so pass `--width` when capturing diff output for a reader.
- `--lx-capacity BYTES` sets the per-core LX budget the occupancy column is measured against (default 1,625,344, the planner's).

Columns beyond the `--basic` set: `LX footprint (stick padded)` is what LX actually holds for the tile; `Address (LX range)` shows `start-end` for an LX tensor and `hbm#N` for an HBM placeholder; `LX live / capacity` is the LX bytes live while the op runs and their share of the budget; `Cost` appears when `--cost` matched; `kernel` appears when more than one kernel directory is present. `Tile Shape` is the per-core tile in the allocation's own dimension order, each dim the smaller of the tensor's own extent and the op's per-core share; `Tile Size` is that tile times the element width; `Format` is the SDSC `dataFormat_` with the element width.

The header carries the whole-run numbers: peak LX live, how many ops joined each dump, `Residency:` (how many joined op outputs are in LX, and the HBM ones counted by reason) and `Relayouts:` (how many of the solver's priced relayout copies it actually kept and what they cost -- a copy priced but not placed is an alternative the solver declined).

Buffer names (`bufN`) are read from the Inductor `.py` next to the artifacts, so `--log` is only needed when that `.py` is absent. INPUT rows carry a `<- producer sdsc_N` pointer and OUTPUT rows a `-> consumer sdsc_N` pointer, matched by LX address within a kernel. The report header prints the peak LX live across ops.

Interactive browser: `python3 sdsc_tui.py DIR` (from this directory) (same `--range`, `--log`, `--cost`, `--lx-capacity`) opens a Textual app: kernels and ops in a tree, tensor rows in a table, every field in a detail pane; `d` toggles detail columns, `/` filters ops, `g`/`b` jump to a tensor's consumer/producer, `]`/`[` grow/shrink the bottom detail pane, `Tab` moves focus between panes (the detail pane scrolls with arrows and PageUp/PageDown and shows the full expression, one term per line), `z` zooms the focused pane to the whole screen, `s` saves an SVG screenshot. `--screenshot FILE.svg` renders headless and exits, for attaching to a PR or Slack. Needs `textual` in the Python that runs the skill (`uv pip install --python $(which python3) textual`). Do not try to drive the interactive app from the Bash tool; use `--screenshot`.

The Tensor Summary Table starts with a `What (-> consumer)` column derived from the SDSC itself: the op class (index gather, LX relayout with its kind and slice counts, restickify, copy, matmul, compute), the LX/HBM placement of inputs and output, and the next op that reads the output's LX address.

Print the script's stdout output directly to the user without modification. Do NOT wrap it in a code block or add any markdown formatting. Do NOT reprint or summarize the output after the tool call.
